# datasets_dealer

输变电工程造价指标抽取工作台及五工程费用核验成果。

## 仓库内容

- 指标抽取工作台Demo 文件夹包含前端页面、本地 Python 服务、来源核验与 Excel 导出源码，以及原有操作说明。
- 指标抽取工作台Demo/outputs 保存指标快照、候选决策、费用报告、文件处理清单和压缩包索引。
- Algorithm 保存配套 OWL 指标标准。
- 成果示例保存菩提及秀清、沛县已导出的核验结果。

工程覆盖常州茅山、扬州秀清、徐州沛县、连云港菩提和江苏镇江圌山。源码与成果取自 D 盘运行的工作台。本次整理日期为 2026-11-25。

## 当前工作方式

前期使用原生工作表读取、PDF 解析和关键扫描页 OCR，结合原件复核形成候选决策。页面点击“开始抽取”时读取预先整理的结果，检查来源文件指纹，并应用已有费用核验结论。待核验及来源冲突的费用指标保留候选和原因，模板对应位置显示“未包含”。有明确依据的实际零值填入数字 0。

数据核验模块集中展示费用指标。模板还包含工程名称、电压和技术条件等已有来源字段，因此模板已填总数和费用核验数采用不同统计范围。

菩提费用构成图沿用批复概算，审定决算金额在文件分析中单列。研究报告中的模拟性能数字未作为本仓库的实际准确率。

## 准备本地资料

公开成果包含上述源码、OWL、核验记录和示例结果。运行时须在仓库根目录自行准备配套“造价数据”文件夹和“2025主网项目指标参考(1).xlsx”模板。两项资料由持有人提供，工程内部相对路径和核验记录中的源文件 SHA-256 必须匹配。

完整工程原件、模型权重及本机依赖由本地保管。只有本仓库文件时，可以阅读核验成果和示例 Excel。完整交互演示还需要配套工程原件与模板。

## 本机启动

当前启动入口适用于 Windows，复用 Codex 本机运行时。

1. 在仓库根目录准备工程原件和配套模板。
2. Python 依赖见 requirements.txt。
3. launch.ps1 使用用户目录下的 .cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe。
4. Excel 导出使用同一运行时的 Node.js 和 @oai/artifact-tool。在“指标抽取工作台Demo/node_modules”建立指向运行时 dependencies/node/node_modules 的目录链接。
5. 双击“指标抽取工作台Demo/启动工作台.bat”，访问 http://127.0.0.1:18864 。
6. 选择工程、模板和 OWL，依次点击“检查配置”“开始抽取”。多个工程可以累计导出。

普通 Python 环境可以安装 requirements.txt 后运行“python 指标抽取工作台Demo/server.py”。Excel 导出仍依赖上述 Node 运行时和 artifact-tool。

## 结果与证据

主数据在 multi_project_records.json，费用决策在 candidate_review.json，费用报告和文件发现分别在 cost_reports.json、document_findings.json。记录包含工程相对路径、单元格或页码、原始数值、单位换算和源文件指纹。

JSON 成果保留原始记录，部分历史记录和示例 Excel 可能含本机绝对路径。迁移时以当前仓库相对目录及真实原件为准。

## 处理边界

部分扫描附件尚未逐页 OCR，专用造价格式和旧版 Word 仍有未解析或失败记录，详见文件处理清单。核验状态会随原件或取值记录变化而失效。

原有“使用说明.md”“实测说明.md”包含历史开发记录，当前行为以源码和候选决策为准。
